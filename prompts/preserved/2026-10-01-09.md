## The fault
After the locate button, the map follows the location and re-centres about once a second. Each re-centre folds an open fan, so a fan on a stack where the user stands closes itself within about a second. Your own finding under -369: `SightingsMap.kt:553-557` calls `MapTapHandler.onCameraMoveStarted` for every reason and `MapTapHandler.kt:119` folds; mode 24, reason 3, five of five early folds.

## The rule
1. **The user moves the map: the fan closes.** A pan, a zoom, a rotation by touch. As today, unchanged.
2. **The map moves without the user meaning it to: the fan stays open,** on screen or off it. It closes only when the user moves the map, taps, or presses Back.
   - **The planner's reading of where the line is, to confirm or challenge:** "without the user meaning it to" is the location following's own moves, small or large. A move the app makes because the user just asked for it (a control they pressed, a search result they chose) is the user's, and still closes the fan as today. If you find a camera move that fits neither, stop and say which.
3. **A fan off screen is left alone.** No rule closes it for being off screen. Back still folds it, as today.
4. **A tap on a fanned icon must hit the icon where it is drawn.** If the map has moved under an open fan, a tap where an icon is now finds it, and a tap where it used to be does not.
