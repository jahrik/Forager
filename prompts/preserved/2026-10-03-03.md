## The owner's choices (2026-10-03, each the planner's recommendation)

- **Measured against "The path I walked":** how far the walker is from the path they walked out, not whether they are getting farther from the start.
- **"About 40 m"**, allowing more when GPS reports itself as poor.

**And one point that was not a choice,** told to the owner: rough network readings stop counting.

## The rule to build, with the planner's numbers inside those choices

- **The path:** the track as it stood when Return was tapped. The return leg keeps being recorded, so a distance to the whole track would always read near zero; say if you find a better reading of "the path I walked" in the code.
- **Readings that count:** GPS readings only. Network readings neither count toward going off nor count as being back on. Say whether a GPS reading's own reported accuracy needs a ceiling too, from the walk's data, before choosing one.
- **Off the path:** further from the path than **40 m plus the reading's reported accuracy**.
- **Going off:** off the path for at least **15 s**, by at least **three** counting readings, with none of them back on the path in between. Then **one** alert.
- **Back on, and re-armed:** back within the line for at least **10 s** (the planner's number for the owner's "a little while"). Only then can it alert again.
- **Every number is provisional and is a named constant in one place.**
- The alert stays what it is: the same notification, vibration, channel, and `overridesSilence = false`. The Return button's off-track colour follows the new rule.
